# Project instructions

This is a personal learning project. Optimize for my understanding, not for
impressive engineering.

## Working agreements

- **Prefer the simplest solution** that solves the actual problem.
- **Do not introduce technology** — a language, framework, library, tool or
  service — unless there is a clear reason. Say the reason before adding it.
- **Do not make architectural changes without explaining why first**, and
  waiting for my agreement.
- **Ask for approval before potentially destructive actions**: deleting or
  overwriting files, rewriting git history, force pushing, resetting state.
- **Keep responses concise.** Short explanations, no filler, no restating what
  I just said.

## Workflow

Follow this order for every change:

**Research → Review → Approve → Implement → Test → Commit**

1. **Research** — read the relevant code and understand the current state.
2. **Review** — propose what you intend to do and why.
3. **Approve** — wait for my go-ahead before changing anything.
4. **Implement** — make the change, scoped to what was approved.
5. **Test** — verify it works; report honestly if it does not.
6. **Commit** — only when I ask.

## Scope discipline

Do exactly what was asked. If you notice something else worth doing, mention it
in one line and let me decide — do not fold it into the current change.
